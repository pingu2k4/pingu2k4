# Asset sources

- Native skill tiles, including .NET and pnpm: [Skill Icons](https://github.com/tandpfun/skill-icons). Original brand backgrounds retained. These tiles are stored locally to keep the displayed set stable.
- Blazor, SQL Server and Railway marks: [Devicon](https://github.com/devicons/devicon). Marks placed in tiles matching Skill Icons' 256 × 256 canvas and 60-unit corner radius.
- Azure Functions: [Azure icon collection](https://github.com/benc-uk/icon-collection).
- esbuild: [project favicon](https://github.com/esbuild/esbuild.github.io/blob/main/src/scripts/favicon.svg).
- Linear: [official brand assets](https://linear.app/brand). The white logomark is embedded unchanged in a matched tile with Linear's blue background.
- WPF and MAUI: custom window/device and wordmark artwork; not official product logos.
- Header: custom SVG artwork for this profile.
- Claude and Codex provider marks: [T3 Code's provider assets](https://github.com/pingdotgg/t3code/tree/main/apps/marketing/public/harnesses). Claude retains its terracotta mark on a cream tile; Codex uses the OpenAI mark on black.
- T3 Code: [official production logo](https://github.com/pingdotgg/t3code/blob/main/assets/prod/logo.svg), in a tile matching the other skill icons.
- Featured project cards: custom SVGs generated by `scripts/update-project-cards.ps1`. Stars come from GitHub's repository API. `scripts/projects.json` lists the exact packages summed for each project.
- NuGet downloads: `scripts/get-nuget-stats.ps1` discovers every package owned by `pingu2k4` through the [NuGet Search API](https://learn.microsoft.com/en-us/nuget/api/search-query-service-resource), including prereleases and Blazor-Web3Modal. It sums each package's complete [NuGet Gallery](https://www.nuget.org/packages?q=owner%3Apingu2k4&prerel=true) version-history table, loading additional rows when necessary. This avoids the stale download totals observed in the search index. Adoption and featured cards share the same validated totals.
- Activity cards: custom SVGs in the same style as the header and featured cards. `scripts/update-activity-cards.ps1` uses the [GitHub GraphQL API](https://docs.github.com/en/graphql/reference/users#contributionscollection) for account/repository statistics, authenticated as `pingu2k4` through the `PROFILE_STATS_TOKEN` Actions secret. Private account activity requires `read:user`; repository totals also require access to the relevant private repositories. Personal and organisation repository totals exclude forks, include archived/private repositories, and paginate. Active repository totals also exclude archived repositories. PRs reviewed uses the API's review-contribution metric rather than every individual review submission.
- Contribution totals, history and highlights use the live [GitHub profile calendars](https://github.com/pingu2k4?tab=overview), fetched by `scripts/contribution-calendar.ps1` for every year since the API-reported account creation date. These calendars include the [anonymized private contribution counts shared on the profile](https://docs.github.com/en/account-and-profile/reference/profile-contributions-reference#who-can-see-your-contributions-and-achievements). The authenticated GraphQL calendar currently disagrees with the profile calendar, so it is not used for these figures. Every year's dates and tooltip counts must parse completely; missing, duplicate or malformed data fails the workflow rather than reporting a successful stale refresh. The persisted `scripts/activity-calendar.json` is an output, never a data source or refresh gate. All-time contributions sum the freshly fetched years; the rolling year includes today and handles leap years. Chart bars, axes, date labels and highlights derive from that same daily series. Weeks start on Monday; boundary weeks may be partial. Busiest weeks/months must be fully covered and completed; the last-30-days tile excludes today. Historical revisions are accepted on every run, without fixed offsets or placeholder totals.
- Every displayed account/repository metric comes from authenticated GraphQL: authored PRs and issues are all-time totals; reviewed PRs cover the rolling year; commits cover the current calendar year. Personal/org stars and org forks/open issues sum paginated non-fork repositories. Repository counts and account age are derived from those API results. Featured stars come from each repository's REST response; download/package counts come from the shared NuGet fetch and the explicit project-to-package mapping.
- The workflow requests a refresh at 03:17 UTC daily, with a second opportunity at 06:43 UTC, and can be dispatched manually. GitHub's scheduled delivery is best effort and can be hours late; neither time is guaranteed. The Actions summary records the trigger, actual UTC start and refreshed contribution totals. It uses the personal token only for account/repository statistics, and the repository-scoped `GITHUB_TOKEN` for commits and featured repository statistics. Regression checks run before any fetch. Source failures fail the run and retain the last committed assets.

Technology and project names and logos identify tools used; they do not imply endorsement.
